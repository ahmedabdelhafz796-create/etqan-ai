# خطة التحقق — الخطوات التي تحتاج تدخلك

> **اقرأ هذا الملف كاملاً.** فيه الحد الفاصل بين ما تم التحقق منه آلياً وما
> يحتاج حساب n8n حقيقي — وهو الفرق بين قالب "يبدو صحيحاً" وقالب "أثبت أنه يعمل".

---

## ما تم التحقق منه آلياً بالفعل ✅

كل قالب يمر عبر `build.py` ولا يُكتب على القرص إلا إذا نجح في:

| الفحص | الحالة |
| --- | --- |
| JSON صالح ويعيد التحليل لنفس البنية (round-trip) | ✅ آلي |
| كل اتصال يشير إلى عقدة موجودة فعلاً | ✅ آلي |
| لا عقد يتيمة، لا أسماء مكررة، لا معرّفات مكررة | ✅ آلي |
| وجود trigger واحد على الأقل | ✅ آلي |
| سياسة إعادة محاولة على كل نداء شبكة | ✅ آلي |
| مسار أخطاء **موصَّل فعلياً** (لا مجرد علم مرفوع) | ✅ آلي |
| حماية من التكرار في كل قالب يبدأ بـ webhook | ✅ آلي |
| **صفر مفاتيح أو أسرار مضمّنة** (مسح بأنماط حقيقية) | ✅ آلي |
| توثيق على الكانفس + ملاحظات على العقد | ✅ آلي |
| كل `typeVersion` مثبّت صراحةً | ✅ آلي |

**بنية العقد نفسها لم تُخمَّن** — استُخرجت من ملفات workflow حقيقية منشورة
(`webhook` 2.1 · `code` 2 · `if` 2.2 · `httpRequest` 4.2 · `crypto` 1 ·
`respondToWebhook` 1.1 · `stickyNote` 1).

---

## ما يحتاج تدخلك ⚠️

**لا أستطيع تسجيل الدخول إلى حساب n8n أو ربط مفاتيح دفع حقيقية.** الفحص الآلي
يثبت أن الملف سليم البنية وخالٍ من الأسرار وموصَّل صح — لكنه **لا يثبت** أن
مفتاح Stripe عندك صحيح أو أن SMTP يرسل فعلاً.

هذه خطوة بشرية بالضرورة، وهي **20–30 دقيقة لمرة واحدة** لكل قالب.

### الخطوات بالضبط

#### 1. جهّز حساب n8n (5 دقائق، مرة واحدة)
- افتح [n8n.io](https://n8n.io) → **Start free** (النسخة السحابية أسهل للبداية).
- أو self-hosted لو تفضّل — القوالب تعمل على الاثنين بدون فرق (وهذا مقصود).

#### 2. استورد القالب (دقيقة)
- `Workflows` → `Import from File`
- اختر `suite/templates/<الفئة>/<القالب>/workflow.json`
- **المتوقع:** يُفتح الرسم كاملاً بدون أي خطأ أحمر، مع الملاحظات الملوّنة ظاهرة.
- **لو ظهر خطأ:** صوّر الشاشة وأرسلها لي — هذا بالضبط ما نريد اكتشافه.

#### 3. املأ الـ Config (3 دقائق)
- افتح عقدة **⚙️ Config** — هي العقدة الوحيدة المطلوب تعديلها.
- في `instant-digital-delivery`: `storeName`, `fromEmail`, `downloadBaseUrl`.
- في `pre-payment-fraud-scoring`: اترك `shadowMode: true` كما هو.

#### 4. اربط الاعتمادات (5 دقائق)
- **Send the product** → اربط اعتماد SMTP.
  (أسهل خيار للتجربة: Gmail بكلمة مرور تطبيق، أو حساب Brevo/Resend مجاني.)
- **Verify signature** / **Sign download link** → ضع النصوص السرية.
  - سر التوقيع: أي نص عشوائي طويل تخترعه أنت. مثال لتوليده:
    ```bash
    openssl rand -hex 32
    ```

#### 5. جرّب بدون دفع حقيقي (10 دقائق) — الأهم
لا تحتاج بوابة دفع للاختبار. استخدم `testMode`:

- في **⚙️ Config** اضبط `testMode: true` (يتجاوز فحص التوقيع فقط).
- اضغط **Execute Workflow** ثم أرسل طلباً تجريبياً:

```bash
curl -X POST '<PRODUCTION_URL_من_عقدة_الويبهوك>' \
  -H 'Content-Type: application/json' \
  -d '{
    "id": "evt_test_001",
    "object": "event",
    "data": { "object": {
      "id": "cs_test_001",
      "payment_status": "paid",
      "amount_total": 4900,
      "currency": "usd",
      "customer_details": { "email": "انت@بريدك.com", "name": "Test Buyer" },
      "metadata": { "product_id": "book-01", "product_name": "Test Product" }
    }}
  }'
```

**المتوقع:**
1. كل العقد خضراء.
2. يصلك بريد فيه زر تحميل.
3. الرابط يحتوي `expires` و `sig`.

**ثم اختبر الحماية من التكرار — وهذه أهم خطوة:**
أرسل **نفس الأمر مرة ثانية**. المتوقع: **لا يصل بريد ثانٍ**، والعقد بعد
Guard تُخرج صفر عناصر. لو وصل بريد مكرر، أخبرني فوراً.

**واختبر أنه يرفض غير المدفوع:**
غيّر `"payment_status": "paid"` إلى `"pending"` و `evt_test_001` إلى
`evt_test_002`. المتوقع: يذهب لفرع **⏸️ Hold** ولا يُرسل شيء.

#### 6. اختبر قالب الاحتيال (5 دقائق)
```bash
curl -X POST '<FRAUD_WEBHOOK_URL>' \
  -H 'Content-Type: application/json' \
  -d '{"orderId":"t1","email":"x9k2m4p8q1@mailinator.com","name":"John Smith","amount":499,"country":"US","ipCountry":"NG"}'
```
**المتوقع:** `riskScore` مرتفع، و `riskReasons` تشرح كل نقطة (نطاق مؤقت +
تضارب جغرافي + مبلغ شاذ)، و `decision: "allow"` لأن `shadowMode` مفعّل.

#### 7. أبلغني بالنتيجة
أرسل لي:
- ✅ نجح / ❌ فشل لكل قالب
- صورة شاشة لأي خطأ
- اسم العقدة التي فشلت + نص الخطأ

وأنا أصلح فوراً وأعيد البناء.

## بعد نجاح الاختبار

1. **التبديل للإنتاج:** `testMode: false` + ضع سر الويبهوك الحقيقي.
2. **اضبط Error Workflow** في `Settings` ليجمع أخطاء كل القوالب في مكان واحد.
3. **قالب الاحتيال:** اتركه `shadowMode: true` **أسبوعاً كاملاً**، اقرأ الأرقام،
   ثم اضبط العتبات على بياناتك أنت قبل التفعيل.
